# ポートフォリオ改修 要件定義書

作成日：2026年9月24日  
対象：[Tatsuki Portfolio](https://github.com/OgawaTatsukicreator/tatsuki.github.io)  
版：第3版・画面構成と掲載内容の検討用

## 1. 改修の目的

採用担当者や企業担当者が、最初の画面で小川樹の人物像と実績を把握し、関心のある内容へ迷わず進めるポートフォリオにする。トップページを5領域の概要、各詳細ページを根拠や経緯が読める場所として整理する。

主な達成目標は次の3点とする。

1. PCでは主要な行き先をヘッダーに常時表示し、クリック先を予測できるようにする。
2. トップページの各概要から、対応する詳細ページへ「詳しく見る」で移動できるようにする。
3. 人物情報、技術、実績、資格、連絡先を、訪問者が目的に応じて拾い読みできる形にする。

参考とする[NRIのサイト](https://www.nri.com/jp/index.html)は、主要項目からカテゴリページへ進み、概要から詳しい情報へ進める階層を持つ。本サイトでは規模に合わせて、各主要項目をそれぞれ1つの詳細ページへ直接つなぐ。NRIの「サービス・ソリューション」ページにはページ内ナビがあるが、本サイトのAchievementsでは、手動スクロールをせず内容を切り替えられる副ナビを追加する。

## 2. 現状と課題

現行の `index.html` は、自己紹介、技術スタック、制作物、経験、資格、連絡先を1ページに並べている。PCでも主要項目はハンバーガーメニューの中にあり、初見ではサイトの構成が見えにくい。制作物・経験には個別ページがある一方、トップページ内移動と別ページへの移動が混在している。

今回の改修では、「主要項目を押すと詳細ページへ移動する」という動作にそろえる。以前の検討案にあったPCヘッダーのドロップダウンは採用しない。親項目のクリックが「開く」か「移動する」かで迷う状態を避け、下位分類はAchievementsページ内の副ナビで示す。

現状の把握には、リポジトリの `README.md`、`index.html`、`pages/*.html`、`js/ui-controls.js`、`css/style.css` を用いた。READMEと個別作品ページの進捗表現には更新時期の差があるため、掲載前に現時点の事実と照合する。

## 3. 想定利用者と情報の優先順位

| 利用者 | 最初に知りたいこと | 主な経路 |
| --- | --- | --- |
| 採用担当者・企業担当者 | 人物像、使った技術、成果の根拠 | Home → About / Skills → Achievements → Contact |
| 制作物に関心がある人 | 課題、本人の担当、制作物の現状 | Home → Achievements → 制作物 → 個別ページ |
| スマートフォン利用者 | 目的のページへ少ない操作で進めること | メニュー → 5つの詳細ページ |

各画面では、短い結論を先に、詳細や根拠を後に置く。Achievementsでは「何をしたか」「自分の役割」「結果・確認できる資料」を区別して表示する。

## 4. サイト構成と画面遷移

### 4.1 ページ一覧

| 画面 | 想定パス | 主な内容 |
| --- | --- | --- |
| Home | `index.html` | 5領域の概要と各「詳しく見る」 |
| About | `pages/about.html` | 基本情報、経歴、人生設計、キャリアプラン |
| Skills | `pages/skills.html` | 技術領域別のアイコンと使用経験 |
| Achievements | `pages/achievements.html` | 制作物・経験・インターンの切替表示 |
| Qualification | `pages/qualification.html` | 取得年月と資格名の縦一覧 |
| Contact | `pages/contact.html` | 連絡手段のアイコンとリンク |

既存の `pages/work-*.html`、`pages/body-contest.html`、`pages/business-model.html` は、内容を点検したうえでAchievementsからの詳細リンクとして再利用する。新規ページのファイル名は実装時に既存の命名規則と合わせるが、画面の役割と遷移先はこの表のとおり固定する。

```text
Home
├─ About
├─ Skills
├─ Achievements
│  ├─ 制作物 ── 個別の制作物ページ
│  ├─ 経験   ── 必要に応じて個別ページ
│  └─ インターン
├─ Qualification
└─ Contact
```

### 4.2 共通ヘッダー

- PCではロゴまたはサイト名を左、`About（自己紹介）`、`Skills（使用技術）`、`Achievements（実績）`、`Qualification（資格）`、`Contact（連絡先）` を右に表示する。見出しの英語表記は `Skills` と `Contact` に統一する。
- ロゴはHomeへ、5つの項目はそれぞれ対応する詳細ページへ、1回のクリックで移動する。
- Homeと全詳細ページで同じ順序・位置・見た目のヘッダーを使う。現在のページを文字と視覚的な印の両方で示し、支援技術にも `aria-current="page"` で伝える。
- ヘッダーはスクロール時も見えるようにする。表示領域を圧迫する画面幅では、ヘッダーを縮めるよりモバイル用メニューに切り替える。
- モバイルではハンバーガーメニュー内に同じ5項目とHomeへのリンクを表示する。開閉状態が分かり、項目選択後にメニューを閉じる。
- 全詳細ページにHomeへ戻る経路を持たせる。ブラウザの戻る操作も自然に機能させる。
- 既存の日英切替を維持する場合は、新しい詳細ページにも切替先と対応する本文を用意する。訳文が未完成のページに、動作しない切替ボタンを表示しない。

### 4.3 遷移時の状態

- `詳しく見る` は必ず対応する詳細ページへ進む。見た目だけのボタンや `#` の仮リンクを残さない。
- 外部サイトへのリンクは遷移先を明示する。別タブで開く場合もリンクの意味が分かる文言を付ける。
- ページ移動後はページ先頭と見出しから読み始められるようにする。固定ヘッダーが見出しを隠さない。
- 主要ナビと「詳しく見る」の名称・順序を全画面で一致させる。

## 5. 画面別の機能・表示要件

### 5.1 Home

ファーストビューでは、名前「小川樹」と、IT・開発・筋力トレーニング／パーソナルトレーニングとの関係を短く伝える。肩書きや実績を断定する文言は、現時点の活動と一致させる。

その下に、次の5つの概要をヘッダーと同じ順序で配置する。各概要は見出し、1～3文の説明、必要なら代表的な写真・数字・アイコン、`詳しく見る` リンクで構成する。

| 領域 | Homeに載せる概要 | 「詳しく見る」の先 |
| --- | --- | --- |
| About | 名前、年齢、趣味を短く示し、経歴や考え方へ誘導 | About |
| Skills | 技術領域と代表的な技術を数件だけ示す | Skills |
| Achievements | 代表的な制作物・経験を2～3件示す | Achievements |
| Qualification | 代表資格と取得年月を示す | Qualification |
| Contact | 利用可能な連絡手段を示す | Contact |

Homeだけで全情報を読み切らせず、各詳細ページに進む理由が分かる概要にする。各領域のラベルと詳細ページの見出しを一致させる。

冒頭に次の基本情報をカードまたは定義リストで表示する。

| 項目 | 表示内容 |
| --- | --- |
| 名前 | 小川 樹 |
| 年齢 | 21歳。基準日または更新方法を明記し、古い年齢を放置しない |
| 出身 | 静岡県伊東市 |
| 学校 | 日本工学院八王子専門学校 |
| 趣味 | 筋力トレーニング |

続いて「これまでの経歴」を時系列で表示する。同月の出来事は1つの年次ブロックにまとめ、日付と内容を混同しない。表示候補の文章は以下とする。

「2026.01 友人の影響で本格的にITに興味を持つ」は、2024年の進学・資格取得との関係が説明なしでは分かりにくいため、初期表示案から外す。「1月のビジネスコンテストに向けて再始動」は開催年と現在の進捗が未確認のため、確認後に成果または今後の予定として掲載する。大会・コンテスト名、順位、所属・参加の表記は公開前に本人資料で照合する。

経歴の後に「人生設計」と「キャリアプラン」を置く。本人の原案にある「周囲の人の幸せ」と「やりたいことを後悔なくやる」を残し、応募先には仕事での行動と目指す役割が伝わる表現にする。次は掲載文案であり、公開前に本人が文意を確認する。

> 周りの人が幸せだと言える状態をつくりたい。そのために、自分もやりたいことを先延ばしにせず、目の前の仕事や挑戦に向き合いたいと考えています。

**キャリアプラン・掲載文案**

| 時期 | 表示文案 |
| --- | --- |
| 5年後 | メンバー一人ひとりの強みや希望を理解し、挑戦と小さな成功を重ねられるチームをつくるリーダーを目指します。自分から提案し、行動することも大切にします。 |

### 5.3 Skills

これまで触れた技術を、用途が分かる領域ごとに表示する。各項目は技術名、アイコン、利用状態、使った場面または制作物へのリンクを持つ。アイコンだけで技術を識別させず、必ず文字ラベルを併記する。

現行サイトに記載された技術をもとにした初期分類案は次のとおり。最終的な掲載範囲と利用状態は、本人の経験とコードで照合する。

| 技術領域 | 表示候補 |
| --- | --- |
| フロントエンド | HTML、CSS、JavaScript、React、Next.js、TypeScript、Tailwind CSS |
| バックエンド・データ | Python、Supabase、Google Apps Script |
| 開発・品質管理 | Git、GitHub、Zod、Vitest |
| インフラ・ネットワーク | ネットワーク／CCNA学習関連の技術・サービス。実務利用と学習中を区別 |

`使用経験あり`、`学習中`、`今後使用予定` を混同しない。使った制作物がある技術は、該当するAchievementsの個別ページへつなぐ。公式ブランドアイコンまたは使用条件が明確なアイコンを用い、色や形がそろわない場合も読みやすい大きさ・余白に統一する。

### 5.4 Achievements

ページ上部に共通ヘッダー、その直下に副ナビ `制作物`、`経験`、`インターン` を置く。副ナビを押すと同じ表示領域の内容を切り替え、訪問者が別のカテゴリへ行くために手動で長いページをスクロールする必要をなくす。これはページ内リンクで下へ飛ばす方式ではなく、選んだカテゴリの内容を表示するタブ方式とする。

- 選択中のタブを文字と視覚的な印で示す。キーボードでも切り替えられる。
- `#works`、`#experience`、`#internships` のようなURLを使い、カテゴリを直接開く・共有する・戻る操作を可能にする。
- 副ナビはスクロール中も共通ヘッダーの下で操作できるようにする。重なって本文やフォーカス位置を隠さない。
- すべてのカテゴリに、見出しと掲載件数が分かる表示を設ける。項目がまだないカテゴリを空白のままにしない。

| カテゴリ | 初期掲載候補 | 各項目に必要な情報 |
| --- | --- | --- |
| 制作物 | シフト提出システム、筋トレ日記・育成アプリ「マソ君の日常」、ほか既存作品のうち事実確認済みのもの | 課題、制作時期、自分の役割、使用技術、現状、GitHub・動作画面・詳細ページ |
| 経験 | 学内ビジネスコンテスト、マッスルゲート静岡大会、関西ビギナーズハッカソン、パーソナルトレーナー活動 | 年月、目的、行動、結果、学んだこと。順位などの根拠 |
| インターン | RIZAPテクノロジーズ株式会社、ウェブフロンティア株式会社 | 参加年月、担当できた範囲、得た知見。公開可能な内容のみ |

制作物カードから既存の個別ページへ進める。コンテストや大会なども十分な資料がある場合に個別ページへ進める。実績の見出しでは「参加」「受賞」「制作」「検証中」などの状態を正確に区別する。
担当範囲や学びがまだ確認できないハッカソン・インターンについては、本人から確認済みの参加先と年月だけを参加記録として掲載する。未確認の詳細を推測で補わず、確認後に項目の本文を拡充する。

### 5.5 Qualification

| 取得年月 | 掲載候補 |
| --- | --- |
| 2026.07 | ビジネス能力検定ジョブパス（B検）2級 |
| 2025.01 | 情報検定（J検）情報システム試験 システムエンジニア認定 |
| 2025.01 | 情報検定（J検）情報システム試験 プログラマ認定 |
| 2024.12 | 基本情報技術者試験 合格 |
| 2024.07 | 情報検定（J検）情報活用試験 2級 |
| 2024.02 | 普通自動車第一種運転免許 |

取得年月は本人の申告に従う。B検2級の2026年7月は、本人に合格・認定月であることを確認済み。資格名は主催団体の[情報活用試験](https://jken.sgec.or.jp/guide/juse.html)、[情報システム試験](https://jken.sgec.or.jp/guide/jsystem.html)、[B検2級](https://bken.sgec.or.jp/guide/guide23.html)の表記に合わせた。必要に応じて資格の詳細・証明へのリンクを置くが、個人情報が写る画像は掲載しない。

### 5.6 Contact

連絡手段をアイコン付きリンクで表示し、アイコンの隣に `メール`、`GitHub` などの文字ラベルを置く。メールはメール作成画面、GitHubは本人のプロフィール、SNSは本人が指定したプロフィールへ移動する。リンク先とボタンの説明を一致させる。

現在のサイトには学校メールアドレスとGitHubプロフィールへのリンクがある。Instagramはサービスのトップページを指しており、本人の連絡先として使えないため、正しいプロフィールURLの確認まで掲載しない。学校メールの継続利用可否も公開前に確認する。連絡手段の優先順位が決まれば、最も望ましい方法を先頭に置く。

## 6. UI・アクセシビリティ要件

- 画面幅に応じてヘッダーとカードの列数を変え、スマートフォンで横スクロールを発生させない。本文の行長を抑え、文字を拡大してもメニューやボタンが重ならない。
- 各ページに1つの主見出しを置き、以降の見出しを階層順に並べる。視覚的な位置だけに頼らず、見出しとリンク名で今いる場所が分かるようにする。
- キーボードでヘッダー、モバイルメニュー、Achievementsのタブ、「詳しく見る」、連絡先を操作できる。フォーカス位置を見失わない。
- メニュー・タブ・現在位置は、色だけに頼らず文字、下線、形などでも示す。コントラストを確保する。
- 固定ヘッダーと副ナビが本文やリンク先の見出しを隠さない。不要な動きを減らす設定にも対応する。
- アイコンと画像には目的に合った代替テキストを付ける。装飾だけの画像は読み上げ対象から外す。
- 既存の静的HTML/CSS/JavaScript構成で実現できる範囲を基本とし、ナビゲーションのためだけに大きなライブラリを追加しない。

判断の根拠には、ソシオメディアの[現在位置と道筋の提示（SHIG 59）](https://www.sociomedia.co.jp/9623)、[メニュー位置の一貫性（SHIG 73）](https://www.sociomedia.co.jp/9762)、[狭い画面での階層整理（SHIG 82）](https://www.sociomedia.co.jp/9801)、[色だけに依存しない情報提示（SHIG 96）](https://www.sociomedia.co.jp/9907)を用いる。

## 7. 受け入れ条件

1. PCのHomeを開いたとき、5つの主要項目がヘッダーに見え、それぞれ1回のクリックで対応する詳細ページへ行ける。
2. Homeの5つの概要にそれぞれ「詳しく見る」があり、対応しないページや仮リンクへ飛ばない。
3. どの詳細ページからもHomeと他の4詳細ページへ移動でき、現在位置を確認できる。
4. モバイルでは5項目が重ならず、メニューの開閉・リンク選択・戻る操作ができる。
5. Aboutに出身・学校を含む基本情報、校正済みの年表、本人が確認した人生設計とキャリアプランがある。価値観、強み・弱みの空欄を表示しない。
6. Skillsで技術が領域別に分かれ、アイコンと文字ラベル、利用状態を確認できる。
7. Achievementsの副ナビから3カテゴリを手動スクロールなしで切り替えられ、直接URL・戻る操作・キーボード操作も成立する。
8. Qualificationは確認済みの取得年月と正式名称を縦一覧で表示し、Contactの各アイコンは正しい連絡先へ移動する。
9. 主要導線をスマートフォンとPCで確認し、リンク切れ、固定ヘッダーによる見出しの隠れ、フォーカスの迷子がない。

## 8. 実装順と未確定事項

まず共通ヘッダーとHomeの概要を作り、5詳細ページとリンクを通す。次にAboutとSkillsの内容、Achievementsの副ナビと既存作品への接続、QualificationとContactの確認済み情報を整える。最後にPC・スマートフォン・キーボードで主要経路を通して確認する。

公開前に本人確認が必要な情報は次のとおり。

- 年齢の基準日または生年月日からの更新方法。
- 人生設計とキャリアプランの掲載文案が本人の意図と合っているか。
- 2026年7月以降のビジネスコンテストの予定と、指している「1月」の年。
- 資格証書に記載された名称と年月の最終照合。B検2級の2026年7月が合格・認定月であることは確認済み。
- InstagramプロフィールのURL、学校メールを今後も連絡先として使うかどうか。
- 技術ごとの使用経験、制作物の現状、実績・インターンの公開可能な内容。

これらの未確定事項は、推測で本文を埋めずに掲載対象から一時的に外す。参加先・参加年月など確認済みの事実は簡潔な参加記録として掲載できる。追加機能やデザインの細部は、上記の画面構造と掲載事実が固まった後に別途決める。
