Works / Hackathon Web App

KYOTABI＋

定番を回り尽くした人に、次の京都を。

写真から気になる寄り道を見つけ、場所を開く。京都を何度も訪れた人に向けて、3人のチームで制作したWebアプリです。

01

プロジェクトの概要

何度も京都へ行くと、有名な観光地はすでに見ている。次の行き先を探しても、よく知られた場所が先に並ぶ。KYOTABI＋は、そんなリピーターが知らない場所へ寄り道するためのアプリです。

一覧では場所の名前を先に出さず、写真と体験を表すタイトルから選べるようにしています。気になる投稿を開き、ポイントを使うと本文を読めます。場所が登録された投稿では、正確な場所とGoogleマップへのリンクも確認できます。

制作の背景

関西ビギナーズハッカソン vol.8（2026年8月）の3人チームによる制作物です。完成版の要件定義・技術選定と公開コードを基に、現在の内容を紹介しています。

02

発見までの流れ

写真で興味を持ち、条件で探し、最後に場所を確かめる。操作の順序を短くまとめました。

03

公開版の機能

01

写真を中心にした投稿一覧

写真と体験のタイトルを入口にします。詳細を見る前に場所名や人気の数字を並べない構成です。

02

条件が伝わる検索結果

キーワードと気分は条件に合う投稿だけを表示し、天気や空き時間などは順位付けに使います。「雨でも大丈夫」など、上位に来た理由も示します。

03

ポイントで開く投稿詳細

初回に10ptを持ち、未閲覧の投稿を1ptで開きます。一度開いた投稿には再度ポイントを使いません。

04

撮影場所を取り込む投稿画面

写真に位置情報があれば読み取り、なければ端末の現在地を使えます。位置情報を取得できない場合は場所を手入力できます。

04

技術と選定理由

ハッカソンの短い制作期間でも公開して試せるよう、ブラウザからすぐ触れられる構成です。検索の並び替えにはAIを使わず、入力条件に対する一致と加点をコードで決めています。

Frontend

Next.js 15 / React 19

画面とルーティングを構成し、Vercelで公開。

Language

TypeScript

投稿と検索条件のデータを型で管理。

Shared posts

Supabase

共有投稿の取得、追加、反応をREST API経由で扱う。

Device state

localStorage

ポイント残高、開いた投稿、自分の投稿を端末内で保持。

Location

EXIF / Geolocation API

写真の撮影地点を読み、取得できないときは現在地や手入力で補う。

Styling

CSS

独立したUIライブラリに頼らず、モバイル向け画面を構成。

05

現在の範囲

アカウント登録なしで公開デモを試せます。共有投稿はSupabaseから読み込みますが、ポイント残高や閲覧履歴は使っている端末のブラウザに保存します。このため、端末を替えても同じ残高や履歴を引き継ぐことはできません。

写真の位置情報は、SNSなどを経由すると削除される場合があります。投稿画面では、端末の現在地を使う操作と場所の手入力を用意しています。

資料の読み方

リポジトリの初期の要件定義書とREADMEには、口コミ件数を使う別案が残っています。このページの機能説明は、公開版のコードと完成版の資料を基準にしています。
