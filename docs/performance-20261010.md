# 性能改善記録（2026年10月10日）

対象は [tatsuki821.me](https://tatsuki821.me/) です。改善前のソースは `af819c9`。配色、文字の形と太さ、写真の構図、レイアウト、リンク先、メニュー、横スライド、スクロール演出を維持して、配信と処理を改善しました。

## 改善の根拠

ユーザーから共有された [モバイルのPageSpeed Insights](https://pagespeed.web.dev/analysis/https-tatsuki821-me/dgqfs2w9nv?form_factor=mobile) と [PCのPageSpeed Insights](https://pagespeed.web.dev/analysis/https-tatsuki821-me/dgqfs2w9nv?form_factor=desktop) を確認しました。測定日時は2026年10月10日18:08 JST、Lighthouse 13.5.0です。

| 指標 | モバイル | PC |
| --- | ---: | ---: |
| パフォーマンス | 51 | 82 |
| FCP（最初の表示） | 7.8秒 | 1.5秒 |
| LCP（主要部分の表示） | 12.8秒 | 2.2秒 |
| TBT（メイン処理のブロック時間） | 284ms | 0ms |
| CLS（表示中の位置ずれ） | 0 | 0.0039 |

転送量は約2.28MBでした。主な負荷は外部フォントのCSS・フォントファイル、PNG画像、年表の位置計測とスタイル更新でした。CSSのGoogle Fonts `@import` は外部CSSを取得した後にフォントの読み込みが始まる構成でした。年表では各項目の位置計測の間にスタイルを変更し、レイアウトの再計算が繰り返されていました。

## 実装内容

### フォント

- 既存の4書体と使用している太さを維持し、使用文字を含むWOFF2をサイト内から配信。
- 日本語フォントはページごとに使用文字を絞り、各HTMLから対応するフォントCSSを直接読み込む。
- 外部フォントCSSの `@import` を削除。欧文の2書体は全ページで共有する。
- OFLと配布元を同梱。IBMの予約名に対応して内部名・CSS名を変更し、元の字形を保持。
- 文字幅の調整・字形の切替機能も元のGoogle Fonts配信に合わせる。詳細ページのCSSは変えず、Shippori Minchoの `palt` と3書体の `ss01` を省き、IBMの `palt` など元の配信にある機能は保持。
- Space Groteskの対象文字範囲も元配信に合わせ、左右・斜めの矢印のフォールバック書体を維持。
- 内容ハッシュを含むファイル名と、文字の追加を確認する開発用スクリプトを用意。

詳細は [配信フォントと更新方法](../assets/fonts/README.md) を参照してください。サイトの実行に追加パッケージやビルドは不要です。

### 画像

背景写真と25個のPNGアイコンを可逆WebPに変換しました。元画像は保持し、変換前後の寸法とRGBA画素の一致を確認しています。SVGはそのまま使用します。

| 対象 | PNG | 可逆WebP | 削減率 |
| --- | ---: | ---: | ---: |
| 背景写真 | 660,306 B | 380,532 B | 42.4% |
| PNGアイコン25個 | 470,452 B | 325,490 B | 30.8% |
| 合計 | 1,130,758 B | 706,022 B | 37.6% |

背景はHTMLで先読みして取得優先度を上げ、画面下のアイコンには遅延読み込みと非同期デコードを指定しました。背景の位置指定、画像の表示サイズ、代替テキストは維持しています。

### スクロール処理

年表の位置をまとめて計測した後に、線の進行度と点灯クラスを更新します。同じ値の再設定と、画面外にある年表の各項目の計測を省きます。スクロールを戻す場合やアンカー移動でも年表の位置を毎回確認します。

画面上から60%の点灯基準、末尾での補正、線の高さの遷移、点の光り方、表示アニメーションは維持しています。変更前との13状態・2年表の比較では、進行度と点灯結果が一致し、矩形の計測回数が130回から58回、書き込み回数が130回から45回になりました。この回数は比較シナリオでの値です。

Windows上のChrome 154、Lighthouse 12.8.2で、トップページを端末別に3回ずつ測定しました。変更前後ともPythonの静的HTTPサーバーを使い、各回で新しいChromeプロファイルを使用しています。以下は各指標の中央値です。

## 表示の確認

- トップ・自己紹介・実績を1440×900と390×844で比較し、文字・要素の配置とページの高さが一致。
- 詳細6ページもPC・スマートフォン幅で比較し、930要素と2,235行の位置・寸法が一致。
- トップ・自己紹介・実績の実際の書体・太さ・使用文字から作成した6組の文字描画比較で、異なる画素は0。
- 全体画像ではWebPのブラウザー合成によるRGB値1段階の差が一部にあるものの、画像の元画素・寸法は一致。
- フォントの使用文字と配信ファイルのSHA-256を `python scripts/build_fonts.py --check` で確認。
- HTMLの文字参照（`&copy;` など）を復号して収録文字を確認。©を含む詳細ページの字形と、元配信フォントの機能設定を独立レビューで照合。
- 全9ページで画像の表示、横幅超過、JavaScriptエラー、ローカル配信ファイルの取得を確認。リンクの文字列と移動先は変更前と一致。
- PCの縦スクロールによる横スライド、スマートフォンのメニュー開閉・Esc・フォーカス復帰、実績・詳細ページ・一覧への戻りを確認。
- 動きを減らす設定とJavaScript無効時にも、全9ページの本文が表示されることを確認。
- 年表は正逆スクロール・上下端の22サンプルで、旧処理と進行度・点灯結果が一致。

## 継続して確認する点

今回のローカル測定でもモバイルのLCPは約6秒です。デザインを維持したままさらに短縮するには、公開環境での再測定を基に、フォントの取得時間と背景の表示時間を確認します。

GitHub Pagesのキャッシュ期間（確認時 `max-age=600`）は変更していません。変更したCSS・JavaScriptのURLには版番号を付け、フォントには内容ハッシュを付けています。文章の更新時は、配信フォントの文字確認と必要に応じた再生成を行ってください。
