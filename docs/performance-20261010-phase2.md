# モバイル性能の追加改善（2026年10月10日）

対象は [tatsuki821.me](https://tatsuki821.me/) です。[前回の改善](performance-20261010.md)を反映した `5a2c91b` を比較の基準とし、年表の初期処理、背景写真、トップページのCSS配信を追加で改善しました。配色、書体、配置、表示内容、リンク先、メニュー、横スライド、スクロール演出は維持します。

## 改善を選んだ根拠

公開サイトの改善前を、Chrome 154・Lighthouse 12.8.2で測定したモバイル1回の結果は、パフォーマンス66、FCP 3.12秒、LCP 5.10秒、TBT 274.5ms、CLS 0でした。

- 年表の初期処理に、ページ全体の高さを読む処理に起因する強制レイアウトがありました。公開サイトのトレースでは、この処理に関連する強制再計算が約144ms、`motion.js` の長い処理が292ms・81msと記録されました。
- 背景写真は可逆WebPでも380,532 Bあり、画像監査ではさらなる圧縮が改善候補でした。
- トップは4つのCSSを取得してから描画する構成でした。公開サイトでの圧縮済みCSSは計約10.7KBでも、複数の通信が初回表示を待たせていました。

LCPの「描画遅延」は画像の取得後から表示までの時間です。その全てがJavaScriptやCSSの実行時間という意味ではありません。また、この公開測定のTBTは0ではありません。ローカル測定と公開測定を分けて記録します。[LCPの内訳の説明](https://web.dev/articles/optimize-lcp)と[描画を待たせるCSSの改善方法](https://developer.chrome.com/docs/lighthouse/performance/render-blocking-resources)を参考にしました。

## 変更内容

### 1. 年表の初期処理を軽くする

年表の位置計測を初回描画の後に開始します。IntersectionObserverで画面近くの年表だけを計測し、遠い年表はブラウザーが提供する位置情報から状態を更新します。遠い年表のためにページ全体の高さや各項目の位置を同期的に読む処理を省きました。

正逆スクロール、アンカー移動、大きなスクロール移動、画面サイズ変更、戻る操作にも対応します。点灯基準の画面上から60%、末尾補正、点の位置、進行度の丸め方、表示アニメーションは既存のままです。スマートフォンで固定表示を使っていないスライダーの不要なリセットも省きました。

### 2. 背景写真を高品質WebPで配信する

| 対象 | 改善前 | 改善後 | 削減率 |
| --- | ---: | ---: | ---: |
| 背景写真 | 380,532 B | 67,982 B | 82.1% |

元PNGから `quality=95, method=6` で生成しました。985×791の寸法、構図、CSSの背景位置・表示サイズを維持しています。画素が完全一致する可逆圧縮ではありません。元画像との輝度SSIMは0.9936で、実際の暗いグラデーションを重ねたPC・スマートフォン表示でも比較しました。元PNGと可逆WebPは保管します。[画像と再生成方法](../images/README.md)を参照してください。

### 3. トップページのCSSを初期HTMLに含める

既存CSSからトップに必要な規則を生成し、HTMLの初期スタイルにまとめました。トップの外部CSS通信は4件から0件になります。フォント宣言、ヘッダー、メニュー、下部セクション、横スライド、スクロール演出、レスポンシブ規則も含むため、途中まで未装飾のまま表示することはありません。JavaScriptを無効にしてもスタイルを適用します。他8ページのCSS配信方法は維持します。

CSSの適用順、値、セレクター、フォントの文字範囲は保持しています。生成ブロックは31,260 B（非圧縮時）です。共有CSSを編集した後は、次のコマンドで反映・確認します。

```bash
python scripts/build_home_styles.py
python scripts/build_home_styles.py --check
```

フォントの生成処理も初期スタイルを自動更新し、その成功後に古いフォントを削除します。`python scripts/build_fonts.py --check` で、配信文字・ハッシュと初期スタイルの一致を確認できます。

## 同条件での測定

Windows上のChrome 154・Lighthouse 12.8.2で、端末別に変更前後を3回ずつ測定しました。Pythonの静的HTTPサーバーを使い、各回で新しいChromeプロファイルを使用しています。公開サイトの測定や、ユーザーから共有されたLighthouse 13.5.0のPageSpeed Insightsとは別の比較です。改善後の実装は `9a9b59a` です。

| 指標（3回中央値） | モバイル変更前 | モバイル変更後 | PC変更前 | PC変更後 |
| --- | ---: | ---: | ---: | ---: |
| パフォーマンス | 71 | 88 | 97 | 99 |
| FCP | 3.32秒 | 1.22秒 | 0.66秒 | 0.65秒 |
| LCP | 6.31秒 | 3.84秒 | 1.27秒 | 0.75秒 |
| TBT | 0ms | 6ms | 0ms | 0ms |
| CLS | 0.00094 | 0.00094 | 0.00131 | 0.00128 |
| リクエスト数 | 44 | 40 | 44 | 40 |
| 転送量 | 1,142,368 B | 818,240 B | 1,142,368 B | 818,240 B |

モバイルのLCPは39.2%、転送量は28.4%減りました。スコアの各回の値は、モバイルが変更前77 / 70 / 71、変更後88 / 86 / 88、PCは変更前97 / 97 / 97、変更後99 / 99 / 99です。全12測定でLighthouseの警告はありません。候補の165配信ファイルのハッシュは、表示比較前と測定後で一致しています。

トップの描画を待たせる外部CSSへの指摘は、変更後の3回とも0でした。主処理全体の時間の中央値は、モバイルで約1,214msから1,125msになりました。LCP対象は同じ `section#top` で、背景写真への画像圧縮の指摘も解消しています。

TBTの中央値はローカルで0msから6msになっており、全ての指標が短縮したという結果ではありません。また、改善後もLCPは約3.84秒です。モバイルの3回目ではシミュレーション上の描画遅延が約3,356ms、主処理全体が約1,113msでした。描画遅延の全てをCPU処理として説明できません。HTMLから読み込む6フォント・約355KBの依存チェーンと、変更していないアイコンの圧縮余地は残っています。

## 公開サイトの確認

実装の `9a9b59a` をmain・newPortfolioへpushし、GitHub Pagesの公開完了と、公開URLで新しい初期スタイル・背景画像・スクリプトを確認しました。その後、公開サイトを同じChrome 154・Lighthouse 12.8.2で3回、毎回新しいChromeプロファイルで測定しました。

| 指標 | 公開変更前（1回） | 公開変更後（3回中央値） |
| --- | ---: | ---: |
| パフォーマンス | 66 | 100 |
| FCP | 3.12秒 | 1.11秒 |
| LCP | 5.10秒 | 1.35秒 |
| TBT | 274.5ms | 49ms |
| CLS | 0 | 0.00085 |

変更後の各回のスコアは97 / 100 / 100で、全3回の警告はありませんでした。変更前は1回なので、その変動幅は評価できません。改善の主な比較根拠は、上記のローカル3回対3回の結果です。この100点は今回のLighthouse測定の中央値で、共有されたPageSpeed Insights（Lighthouse 13.5.0）の再測定結果ではありません。

公開サイトにはGitHub Pagesの圧縮とCDNがあるため、非圧縮のローカルサーバーと値が異なります。通信・端末・測定環境によって今後のスコアも変動します。

公開後の全9ページがHTTP 200で、配信フォントとスクリプトの更新も確認しました。横幅超過、画像の破損、JavaScriptエラー、取得失敗、新しいコンソールエラー、Google Fontsへの通信はありません。記録した55件のフォント・33件の画像の応答は全て200でした。トップでは新しい背景と使用する6フォントの取得を確認し、PC表示も目視で確認しました。

公開測定の1回目と3回目には、出所が特定されていない強制レイアウトが約81ms・154ms記録され、2回目の監査表は空でした。年表の処理改善によって全ての強制レイアウトがなくなったという結果ではありません。

- 全9ページを1440×900と390×844で、初回読み込みからページ末尾まで確認。安定後の文字の各行・要素の位置、寸法、書体、太さ、色、変形は変更前と完全一致し、両幅合計296リンクの表示名・移動先も一致しました。
- 比較した36枚の画像のうち32枚は全画素一致。差がある4枚はトップのPC・スマートフォンの上部／全体画像で、差の範囲は背景写真の矩形内だけでした。PCのRGB最大差は6、スマートフォンは3です。

- 年表の状態モデル44件とPCスライダー7件を照合。実ブラウザーでもアンカー移動・戻る・再読み込み・履歴復元・幅変更の36状態で、年表の進行度・点灯結果・スクロール位置が一致しました。
- 状態モデルで、初期表示と年表が遠い位置にあるスクロールの高さ・矩形の同期計測が0件であることを確認しました。

## 更新時の注意

初期スタイルを直接編集せず、元の共有CSSを編集して生成します。CSS・JavaScriptを変更したページの参照URLは版番号を更新します。フォントの追加・再生成は[フォント更新手順](../assets/fonts/README.md)に従います。サイトの実行には追加パッケージやビルドは不要です。
